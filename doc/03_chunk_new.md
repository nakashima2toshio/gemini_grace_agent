（1）* ソースの箇所:
qa_generation/semantic.py/class SemanticCoverage:
・qa_generation/semantic.py の _chunk_by_paragraphs および _split_into_sentences


チャンクの3方式の説明：

1. 階層分割 (1): 段落や文といった文章構造をリスペクトして分けつつ、
   1. Recursive Character Text Splitter（再帰的文字分割）
2. 意味解析 (2): 構造が同じでも「意味」が離れていればそこで切り、
   1. Semantic Chunking（セマンティックチャンク）
3. 重複付与 (3): 最後に、切れた場所の前後を「オーバーラップ」でつなぎ止める。
   1. Chunk Overlap(チャンクオーバーラップ）

3方式の詳細・説明：

1. Recursive Character Text Splitter（再帰的文字分割）【（独自実装による階層的分割）】

* ソースの箇所: qa_generation/semantic.py の _chunk_by_paragraphs および _split_into_sentences
* 仕組み: 完全な LangChain のクラスではありませんが、同様の設計思想で動いています。
  1. まず 「段落（改行2つ）」 で分ける。
  2. 段落が大きすぎる場合は 「文（句読点）」 で分ける。
  3. 文が長すぎる場合は 「トークン単位」 で強制分割する。
* 効果: 文章の構造（大きな塊から小さな単位へ）を壊さないように段階的に分割を試みています。

2. Semantic Chunking（セマンティックチャンク）【（オプション機能）】

* ソースの箇所: make_qa.py の引数 --use-similarity および --similarity-threshold
* 仕組み: qa_generation/semantic.py の _calculate_sentence_similarities メソッドで実装されています。
* 動作: 各文章をベクトル化（Embedding）し、隣り合う文章の「意味の近さ」を計算します。類似度が設定したしきい値（デフォルト
  0.7）を下回った場所を「話題の転換点」とみなして分割します。
* 効果: ご説明にある通り、文字数に関係なく「話の内容が変わったタイミング」で適切に区切ることができます。

3. チャンクオーバーラップ（Chunk Overlap）

* ソースの箇所: make_qa.py の引数 --overlap-tokens
* 仕組み: qa_generation/semantic.py の _apply_chunk_overlap メソッドで実装されています。
* 動作: チャンクを作成した後、前のチャンクの末尾にある文章を、指定されたトークン数分だけ次のチャンクの先頭にコピーします。
* 効果: ご説明にある通り、「代名詞（それ、彼など）」が何を指しているかという文脈を維持し、情報の分断を防いでいます。

### チャンク方式の具体例：

1. Recursive Character Text Splitter（再帰的文字分割）
   「文章の論理構造を壊さない」ための技術

* 有効な場面: 章、節、項がはっきりしているマニュアルや報告書
* 具体例:
  ```text
  【元の文章】
  第1章：導入手順。まずは電源を入れてください[改行]
  次に設定ボタンを押します。 ...（非常に長い説明）... [改行]
  第2章：トラブルシューティング
  ```
* 動作:
  1. まず「第1章」と「第2章」の間の大きな改行で分けようとします。
  2. 「第1章」の中身がまだ長すぎる場合、次の句読点（。）で分けます。
* なぜ有効か:
  もし「文字数だけ」で機械的に切ってしまうと、「第2章：トラ」 / 「ブルシューティング」
  のように、見出しの途中で切れて意味不明になります。この手法なら、必ず「意味の区切り（改行や句点）」で切れるため、AIが内容を正しく理解で
  きます。

---

2. Semantic Chunking（セマンティックチャンク）
   「話のトピックが変わった瞬間」を見逃さない技術

* 有効な場面: 雑談が混じるインタビュー記事、トピックが多岐にわたるブログ
* 具体例:
  > 【元の文章】
  > 「...最新のGemini 2.0は非常に高速ですね。ところで、昨日のランチで食べたカレーが凄く美味しくて、スパイスの香りが...」
  >
* 動作:

AIが文章の意味（ベクトル）を分析し、「Gemini（技術の話）」と「カレー（食事の話）」の間の意味的な距離が急激に離れたことを検知します。構
造上は同じ段落内であっても、ここでスパッと分割します。

* なぜ有効か:

RAGで「Geminiの性能は？」と質問した際、カレーの話が混ざった回答が返ってくるのを防げます。「意味の純度」が高いチャンクを作ることで、検
索のノイズを劇的に減らせます。

---

3. チャンクオーバーラップ（Chunk Overlap）
   「文脈の橋渡し」をするための技術

* 有効な場面: 代名詞（それ、彼、同社など）が多用される説明文
* 具体例:
  > 【分割ポイント】
  > チャンクA：「Appleは2024年に新型のiPhoneを発売しました。」
  > （ここで分割）
  > チャンクB：「同社はさらに、独自のAIチップも発表しています。」
  >
* 動作（オーバーラップ50トークンの場合）:
  チャンクBの冒頭に、チャンクAの末尾を少し含ませます。
  > 新チャンクB：「（...iPhoneを発売しました。）同社はさらに、独自のAIチップも発表しています。」
  >
* なぜ有効か:

オーバーラップがない場合、検索でチャンクBだけがヒットすると、AIは「同社ってどこ？」となり、正しい回答ができません。前の文章を少し含ま
せることで、「同社＝Apple」という文脈を維持したまま回答させることができます。

---

結論：make_qa.py における「3段構え」の相乗効果

あなたの make_qa.py は、これらを以下のように組み合わせて「最強のチャンク」を作っています。

1. 階層分割: まず文章の「見た目の構造（段落）」を壊さない。
2. 意味解析: 見た目がつながっていても「話の中身」が変われば切り離す。
3. 重複付与: 切り離した境界線に「のりしろ（オーバーラップ）」を付けて、文脈が途切れないように接着する。

この結果、「トピックが明確」かつ「文脈が完結している」理想的なデータセットが作成され、それがRAGの回答精度の高さ（GRACE
Agentの強み）に直結しています。

## チャンク分割技術詳細 (qa_generation/semantic.py/SemanticCoverage)

## 1. 概要

`agent_rag.py` (および `make_qa.py`) で採用されているチャンク分割の中核クラスは **`SemanticCoverage`** です。
このクラスは、単なる文字数による機械的な分割ではなく、文書の「意味的なまとまり（段落や文）」を考慮した高度な分割（セマンティックチャンキング）を提供します。

## 2. 実装クラス情報

* **ファイルパス**: `qa_generation/semantic.py`
  * (旧互換性のため `helper_rag_qa.py` からも参照可能)
* **クラス名**: `SemanticCoverage`

## 3. 主な機能とロジック

`SemanticCoverage` クラスは、以下の優先順位とロジックで文書を分割します。

### 3.1 段落優先分割 (`prefer_paragraphs=True`)

最も基本的な意味のまとまりである「段落」を維持することを最優先します。

1. **段落抽出**: 空行 (`\n\n`) でテキストを分割し、段落を抽出します。
2. **トークン数チェック**:
   * 段落のトークン数が `max_tokens` 以内であれば、その段落を1つのチャンクとします。
   * 段落が `max_tokens` を超える場合のみ、さらに細かい「文単位」での分割（下記 3.2）を行います。

### 3.2 文単位の分割とMeCab対応

段落内でさらに分割が必要な場合、または段落優先モードが無効な場合は、文単位で処理します。

* **日本語対応 (MeCab)**:
  * 環境に `MeCab` がインストールされている場合、形態素解析を用いて正確な文の境界（「。」「！」など）を判定します。
  * これにより、括弧内や引用符内の句点による誤分割を防ぎます。
* **フォールバック**:
  * MeCabが利用できない場合は、正規表現 (`[^。．.！？!?]+[。．.！？!?]`) を用いて分割します。

### 3.3 チャンクの統合と調整

分割されたチャンクに対し、以下の調整を行います。

* **小チャンクの統合 (`min_tokens`)**:
  * 生成されたチャンクが `min_tokens` (デフォルト50) 未満の場合、隣接する前のチャンクとの統合を試みます。
  * 統合後のサイズが許容範囲内であればマージし、文脈の断片化を防ぎます。
* **強制分割**:
  * 単一の文が `max_tokens` を超える巨大な文である場合のみ、トークン数ベースで強制的に分割します（最終手段）。

### 3.4 オーバーラップ (`overlap_tokens`)

文脈の連続性を保つため、チャンク間に重複部分を持たせることができます。

* **ロジック**: 前のチャンクの末尾にある文を、指定されたトークン数 (`overlap_tokens`) に収まる範囲で次のチャンクの冒頭にコピーします。
* これにより、チャンクの境界で情報が分断されることを防ぎ、検索精度（RAG）を向上させます。

## 4. コード例 (利用イメージ)

```python
from qa_generation.semantic import SemanticCoverage

# 初期化 (Gemini Embedding APIを使用)
semantic = SemanticCoverage(embedding_model="gemini-embedding-001")

# ドキュメント
text = "..."

# チャンク分割実行
chunks = semantic.create_semantic_chunks(
    document=text,
    max_tokens=400,      # 最大トークン数
    min_tokens=150,      # 最小トークン数
    prefer_paragraphs=True, # 段落優先
    overlap_tokens=0     # オーバーラップなし
)

# 結果の確認
for chunk in chunks:
    print(f"ID: {chunk['id']}, Type: {chunk['type']}, Tokens: {len(chunk['text'])}")
```

## 5. 設定パラメータ (UI/スクリプト)

`agent_rag.py` の「Q/A生成」画面や `make_qa.py` では、以下のパラメータでこのクラスを制御しています。


| パラメータ名        | 説明                                       | デフォルト値 |
| :------------------ | :----------------------------------------- | :----------- |
| `max_tokens`        | チャンクの最大トークンサイズ               | 400          |
| `min_tokens`        | チャンクの最小サイズ（これ以下は統合検討） | 150          |
| `prefer_paragraphs` | 段落単位の分割を優先するか                 | True (固定)  |
| `overlap_tokens`    | 前のチャンクとの重複トークン数             | 0 (設定可)   |
